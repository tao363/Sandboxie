# 验证清单

本文件包含 init 模式和 garden 模式的验证清单。执行对应模式的收尾阶段时逐项核对。

---

# Part 1: Init 模式验证清单

在 Phase 7 中逐项核对。每项标记 ✅ 或 ❌ 并注明问题。

## 结构完整性

- [ ] AGENTS.md 或 CLAUDE.md 存在于项目根目录
- [ ] 导航文件行数 < 120 行（目录不是百科全书）
- [ ] docs/ 目录已创建
- [ ] docs/architecture/overview.md 存在且已填充
- [ ] docs/guides/coding-conventions.md 存在且已填充
- [ ] 导航文件中引用的每个文件路径都实际存在
- [ ] 目录结构说明与实际目录一致
- [ ] docs/.doc-meta.json 已创建（新鲜度注册表）

## 内容质量

- [ ] architecture/overview.md 包含模块职责表和数据流描述
- [ ] coding-conventions.md 的约定可从现有代码中得到印证（非凭空捏造）
- [ ] 常用命令已验证可执行（至少 build/test）
- [ ] 关键约定来源于项目实际（lint 配置、编译器设置等），非泛泛而谈
- [ ] 技术栈信息与项目配置文件一致

## Agent 可用性（模拟测试）

- [ ] **导航测试**: 仅看导航文件，能否在 30 秒内找到"如何构建项目"
- [ ] **新功能测试**: 仅看导航文件 + docs/，能否明确知道"在哪里加新代码"
- [ ] **约定测试**: 仅看 coding-conventions.md，能否写出符合项目风格的代码
- [ ] **恢复测试**: 仅看 git log，能否理解项目当前状态和下一步

## 渐进式披露

- [ ] L0（必读）文档总 token 数合理（< 2000 tokens）
- [ ] 每个文档都自包含——不需要同时打开其他文档才能理解
- [ ] 深层内容有明确的"何时需要读"的指引

## 新鲜度基础设施

- [ ] docs/.doc-meta.json 包含所有文档的注册记录
- [ ] 每个注册记录都有 content_hash（SHA-256）
- [ ] 每个注册记录都有 mapped_code_paths（关联代码路径）
- [ ] mappings.rules 中包含项目特定的代码-文档映射
- [ ] last_gardened_commit 记录了当前 HEAD

## 机械化校验

- [ ] 文档交叉引用完整性可通过脚本验证
- [ ] 导航文件中的所有链接都指向存在的文件

## 反模式检查

- [ ] 没有单个文件 > 300 行（如有，应拆分）
- [ ] 没有重复信息散落在多个文件中（单一来源原则）
- [ ] 没有含糊的"应该"式规则——要么具体到可执行，要么删除
- [ ] 没有只描述理想状态但不说如何验证的约定
- [ ] 导航文件没有包含可以放在子文档中的详细内容

---

## 项目规模适配检查

### 小型项目（< 5000 LoC）
- [ ] 没有过度文档化（不需要 ADR、domain-map、quality 等）
- [ ] 导航文件 + 2-3 个核心文档即可

### 中型项目（5K-50K LoC）
- [ ] 标准文档体系已建立
- [ ] guides/ 中至少有 coding-conventions.md

### 大型项目（> 50K LoC）
- [ ] 按领域分割文档
- [ ] domain-map.md 已建立
- [ ] quality.md 已建立
- [ ] beliefs.md 已建立
- [ ] 多级导航已建立

# Part 2: Garden 模式验证清单

在 Phase G5 中逐项核对。

## Diff 分析完整性

- [ ] 正确识别了 diff 基准（last_gardened_commit 或 merge-base）
- [ ] 变更文件列表已获取
- [ ] 变更已分类（新增/修改/删除/重命名）
- [ ] 受影响的文档列表已确定（通过 domain-to-doc 映射）

## 新鲜度扫描

- [ ] 所有注册文档都进行了新鲜度检查
- [ ] STALE_CODE 状态的文档已被识别
- [ ] ORPHAN 状态的文档已被处理
- [ ] NEW（未注册）的文档已被识别

## 定向更新质量

- [ ] 自动更新仅包含事实性修正
- [ ] 叙述性/架构性变更已征询用户意见
- [ ] 每个更新都有一行摘要说明
- [ ] 更新后的文档内容准确反映代码现状
- [ ] 以评审者视角验证：更新合理且保守

## 导航同步

- [ ] 导航文件中的文档索引与 docs/ 实际文件一致
- [ ] 所有交叉引用链接有效
- [ ] 新增文档已添加到导航索引
- [ ] 删除的文档已从导航索引移除
- [ ] domain-map.md（如存在）与代码模块结构一致

## 新鲜度注册表更新

- [ ] docs/.doc-meta.json 已更新
- [ ] 更新的文档有新的 content_hash
- [ ] last_verified 和 verified_at_commit 已更新
- [ ] last_gardened_commit 已更新为当前 HEAD
- [ ] 新文档已添加注册记录
- [ ] 删除的文档已移除注册记录

## 反模式检查（Garden 特有）

- [ ] 没有对文档做不必要的修改（无 diff 支持的臆造变更）
- [ ] 没有跨文档的不一致信息
- [ ] 没有遗漏的陈旧内容（特别是路径引用和模块列表）
- [ ] 没有被标记为 STALE 但未处理的文档

---
