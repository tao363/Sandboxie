## 项目概述

**Sandboxie** 是一个基于沙箱的 Windows 隔离软件，通过内核驱动和用户态 DLL 注入技术，实现对应用程序的完全隔离。

### 主要功能

1. **安全隔离**：在虚拟环境中运行不受信任的程序，防止其对系统造成永久性修改
2. **测试环境**：为软件测试提供干净、可恢复的运行环境
3. **隐私保护**：隔离浏览器和应用程序，防止数据泄露和跟踪
4. **多实例运行**：允许同时运行同一程序的多个独立实例
5. **可恢复性**：所有修改都可以轻松删除，系统可快速恢复到原始状态

### 技术特点

- **透明隔离**：应用程序无感知，无需修改源代码
- **多层防护**：内核驱动 + 用户态 Hook 双重保护
- **细粒度控制**：可配置文件、注册表、网络等各种资源的访问规则
- **跨架构支持**：支持 x86、x64、ARM64、ARM64EC

### 1. 内核驱动层 (SbieDrv.sys)

**源码位置**：`Sandboxie/core/drv/`

**核心职责**：

- **系统调用拦截**：在内核层拦截所有 NT 系统调用
- **进程监控**：监控进程创建和销毁，识别沙箱进程
- **文件系统过滤**：使用 Minifilter 框架拦截文件操作
- **注册表虚拟化**：重定向注册表访问
- **IPC 隔离**：控制进程间通信

**关键文件**：
- `driver.c` - 驱动入口和初始化
- `syscall.c` - 系统调用拦截管理
- `process.c` - 进程管理和监控
- `file.c` - 文件系统过滤
- `key.c` - 注册表虚拟化
- `ipc.c` - IPC 隔离

### 2. 服务层 (SbieSvc.exe)

**源码位置**：`Sandboxie/core/svc/`

**核心职责**：

- **配置管理**：读取和管理 Sandboxie.ini 配置
- **进程启动**：启动沙箱进程并注入 DLL
- **驱动通信**：通过 IOCTL 与内核驱动通信
- **GUI 服务器**：为 UI 提供 RPC 接口
- **资源管理**：管理沙箱资源和清理

**关键文件**：
- `GuiServer.cpp` - GUI 通信服务器
- `DriverAssist.cpp` - 驱动辅助功能
- `MountManager.cpp` - 挂载点管理

### 3. 注入层 (SbieDll.dll)

**源码位置**：`Sandboxie/core/dll/`

**核心职责**：

- **API Hook**：Hook Windows API 函数
- **路径重定向**：重定向文件和注册表路径
- **透明拦截**：拦截应用程序的系统调用
- **资源虚拟化**：虚拟化各种系统资源

**关键文件**：
- `dllmain.c` - DLL 入口和初始化
- `dllhook.c` - Hook 管理
- `file.c` - 文件操作 Hook
- `key.c` - 注册表操作 Hook
- `advapi.c` - AdvAPI Hook

### 4. 用户界面层

**Sandboxie Plus** (Qt-based)：
- **源码位置**：`SandboxiePlus/SandMan/`
- **特点**：现代化界面，支持所有新特性

**Sandboxie Classic** (MFC-based)：
- **源码位置**：`Sandboxie/apps/control/`
- **特点**：传统界面，不再积极开发

## 工作原理

### 系统调用拦截机制

Sandboxie 的核心是**系统调用拦截**，通过在内核层拦截系统调用，实现对沙箱进程的完全控制。

#### 拦截流程

```
应用程序调用 API
    ↓
用户态 DLL Hook (SbieDll.dll)
    ↓ (可能重定向)
系统调用 (syscall/sysenter)
    ↓
内核驱动拦截 (SbieDrv.sys)
    ↓ (检查权限、重定向路径)
实际系统调用执行
    ↓
返回结果
```

#### 代码实现

**驱动层初始化** (`syscall.c`):

```c
_FX BOOLEAN Syscall_Init(void)
{
    // 初始化系统调用列表
    if (! Syscall_Init_List())
        return FALSE;

    // 建立系统调用表
    if (! Syscall_Init_Table())
        return FALSE;

    // 初始化服务数据
    if (! Syscall_Init_ServiceData())
        return FALSE;

    return TRUE;
}
```

**系统调用表结构** (`syscall.h`):

```c
typedef struct _SYSCALL_ENTRY {
    LIST_ELEM list_elem;
    USHORT syscall_index;        // 系统调用索引
    USHORT param_count;          // 参数数量
    ULONG ntdll_offset;          // ntdll 中的偏移
    void *ntos_func;             // 内核函数地址
    P_Syscall_Handler1 handler1_func;  // 处理函数1
    P_Syscall_Handler2 handler2_func;  // 处理函数2
    UCHAR disabled;              // 是否禁用
    UCHAR approved;              // 是否批准
    USHORT name_len;             // 名称长度
    UCHAR name[1];               // 函数名称
} SYSCALL_ENTRY;
```

### DLL 注入机制

Sandboxie 使用**早期注入**技术，在进程初始化的最早阶段注入 DLL。

#### 注入流程

```
1. 驱动监测到进程创建
   ↓
2. 驱动注入 LowLevel.dll (早期注入)
   ↓
3. LowLevel.dll 加载 SbieDll.dll
   ↓
4. SbieDll.dll 初始化并 Hook API
   ↓
5. 应用程序正常启动 (已被 Hook)
```

#### 代码实现

**注入入口** (`inject.c`):

```c
ULONG_PTR DetourFunc(INJECT_DATA *inject)
{
    NTSTATUS status;
    UNICODE_STRING* pDllPath;
    HANDLE ModuleHandle;
    P_Dll_Ordinal1 SbieDllOrdinal1;

    // 加载 SbieDll.dll
    status = SBIELOW_CALL(LdrLoadDll)(
        NULL, NULL, pDllPath, &ModuleHandle);

    // 调用 SbieDll 的初始化函数
    SbieDllOrdinal1 = (P_Dll_Ordinal1)FindDllExport(
        ModuleHandle, (UCHAR*)1, &err);

    SbieDllOrdinal1(inject);

    return 0;
}
```

**Hook 管理** (`dllhook.c`):

```c
typedef struct _MODULE_HOOK {
    LIST_ELEM   list_elem;
    HMODULE     module;      // 被 Hook 的模块
    POOL*       pool;        // 内存池
    LIST        vTables;     // 虚函数表
    LIST        trace;       // 跟踪信息
} MODULE_HOOK;

_FX void SbieDll_HookInit()
{
    InitializeCriticalSection(&Dll_ModuleHooks_CritSec);
    List_Init(&Dll_ModuleHooks);
}
```

## 关键技术

### 1. 文件系统重定向

**原理**：Copy-on-Write (写时复制)

#### 路径映射

```
真实路径: C:\Windows\System32\test.txt
沙箱路径: C:\Sandbox\DefaultBox\drive\C\Windows\System32\test.txt
```

#### 操作规则

| 操作类型 | 处理方式 |
|---------|---------|
| **读取** | 优先读取沙箱路径，不存在则读取真实路径 |
| **写入** | 先复制到沙箱路径（如果不存在），然后在沙箱中修改 |
| **删除** | 仅在沙箱中标记删除，不影响真实文件 |
| **创建** | 直接在沙箱路径创建 |

#### 代码实现

**路径转换** (`file.c`):

```c
NTSTATUS File_GetName(
    HANDLE RootDirectory,
    UNICODE_STRING *ObjectName,
    WCHAR **OutTruePath,   // 输出：真实路径
    WCHAR **OutCopyPath,   // 输出：沙箱路径
    ULONG *OutFlags)       // 输出：标志
{
    // 解析路径
    // 判断是否需要重定向
    // 生成沙箱路径
    // 返回两个路径供后续使用
}
```

**文件访问控制**：

```c
#define FILE_DENIED_ACCESS ~(                                           \
    STANDARD_RIGHTS_READ | GENERIC_READ | SYNCHRONIZE | READ_CONTROL |  \
    FILE_READ_DATA | FILE_READ_EA | FILE_READ_ATTRIBUTES | FILE_EXECUTE)
```

### 2. 注册表虚拟化

**原理**：类似文件系统，注册表操作被重定向到沙箱专用的注册表路径

#### 路径映射

```
真实注册表: HKEY_CURRENT_USER\Software\MyApp
沙箱注册表: HKEY_USERS\<SID>_Classes\Sandbox\<BoxName>\user\current\Software\MyApp
```

#### 实现机制

- **读取优先级**：沙箱注册表 → 真实注册表
- **写入隔离**：所有写入操作重定向到沙箱注册表
- **删除保护**：删除操作仅影响沙箱注册表

### 3. 进程隔离

#### 进程标记

驱动为每个沙箱进程维护一个 `PROCESS` 结构：

```c
typedef struct _PROCESS {
    LIST_ELEM list_elem;
    HANDLE pid;              // 进程 ID
    BOX *box;                // 所属沙箱
    WCHAR *image_name;       // 映像名称
    ULONG flags;             // 标志
    // ... 更多字段
} PROCESS;
```

#### 子进程继承

```c
static void Process_NotifyProcessEx(
    PEPROCESS ParentId,
    HANDLE ProcessId,
    PPS_CREATE_NOTIFY_INFO CreateInfo)
{
    // 检查父进程是否在沙箱中
    PROCESS *parent_proc = Process_Find(ParentId, NULL);

    if (parent_proc && parent_proc->box) {
        // 父进程在沙箱中，子进程也加入沙箱
        Process_Create(ProcessId, parent_proc->box, ...);
    }
}
```

#### IPC 隔离

- **命名对象隔离**：重定向命名管道、事件、互斥体等
- **窗口消息过滤**：限制跨沙箱的窗口消息
- **剪贴板隔离**：可选的剪贴板访问限制

### 4. 令牌（Token）隔离

**功能**：创建受限的访问令牌，降低沙箱进程的权限

#### 令牌修改

```
原始令牌
    ↓
移除管理员权限
    ↓
限制访问敏感资源
    ↓
添加沙箱特定的 SID
    ↓
受限令牌
```

#### 安全增强

- **权限降级**：移除不必要的特权
- **完整性级别**：设置较低的完整性级别
- **SID 限制**：添加限制性 SID

### 5. 网络隔离

**功能**：通过 Windows Filtering Platform (WFP) 实现网络隔离

#### 网络控制

- **防火墙规则**：为每个沙箱配置独立的防火墙规则
- **DNS 控制**：阻止或重定向 DNS 查询
- **代理支持**：强制使用 SOCKS5 代理

## 执行流程

### 完整执行示例

**场景**：在沙箱中运行 notepad.exe 并保存文件

#### 步骤 1：启动请求

```
用户操作：点击"在沙箱中运行" → notepad.exe
    ↓
SandMan.exe (UI)
    ↓ RPC 调用
SbieSvc.exe (服务)
```

#### 步骤 2：进程创建

```
SbieSvc.exe
    ↓ 通知驱动
SbieDrv.sys
    ↓ 创建进程
CreateProcess("notepad.exe")
    ↓ 进程创建通知
Process_NotifyProcessEx()
    ↓ 标记为沙箱进程
Process_Create(pid, box, ...)
```

#### 步骤 3：DLL 注入

```
SbieDrv.sys
    ↓ 早期注入
LowLevel.dll 注入到 notepad.exe
    ↓ 加载主 DLL
SbieDll.dll 加载
    ↓ 初始化
Dll_InitInjected()
    ↓ Hook API
Hook ntdll.dll, kernel32.dll, ...
```

#### 步骤 4：应用程序运行

```
notepad.exe 启动
    ↓ (所有 API 已被 Hook)
正常运行，但所有操作被拦截
```

#### 步骤 5：文件保存操作

```
用户操作：保存文件到 C:\test.txt
    ↓
notepad.exe 调用 CreateFile("C:\test.txt", WRITE)
    ↓ 被 SbieDll.dll Hook
File_NtCreateFileImpl()
    ↓ 路径转换
File_GetName()
    TruePath:  C:\test.txt
    CopyPath:  C:\Sandbox\DefaultBox\drive\C\test.txt
    ↓ 重定向调用
NtCreateFile("C:\Sandbox\DefaultBox\drive\C\test.txt", WRITE)
    ↓ 系统调用
进入内核
    ↓ 驱动拦截
SbieDrv.sys: Syscall_Handler()
    ↓ 验证权限
检查沙箱配置，允许写入
    ↓ 执行实际操作
文件写入沙箱路径
    ↓ 返回
返回成功给 notepad.exe
```

**结果**：
- 真实的 `C:\test.txt` 未被修改
- 文件实际保存在 `C:\Sandbox\DefaultBox\drive\C\test.txt`
- notepad.exe 认为文件已保存到 `C:\test.txt`

#### 步骤 6：清理沙箱

```
用户操作：删除沙箱内容
    ↓
SandMan.exe → SbieSvc.exe
    ↓
删除目录 C:\Sandbox\DefaultBox\
    ↓
所有修改消失，系统恢复原状
```

### 文件读取流程

**场景**：读取 `C:\Windows\System32\notepad.exe`

```
应用程序调用 CreateFile("C:\Windows\System32\notepad.exe", READ)
    ↓ Hook 拦截
SbieDll.dll: File_NtCreateFileImpl()
    ↓ 路径转换
File_GetName()
    TruePath:  C:\Windows\System32\notepad.exe
    CopyPath:  C:\Sandbox\DefaultBox\drive\C\Windows\System32\notepad.exe
    ↓ 检查沙箱路径
if (CopyPath exists)
    打开 CopyPath  // 沙箱中有修改版本
else
    打开 TruePath  // 使用真实文件
```

### 注册表操作流程

**场景**：写入注册表 `HKCU\Software\MyApp\Setting = "value"`

```
应用程序调用 RegSetValueEx(HKCU\Software\MyApp\Setting, "value")
    ↓ Hook 拦截
SbieDll.dll: Key_NtSetValueKeyImpl()
    ↓ 路径重定向
Key_GetName()
    TruePath:  HKCU\Software\MyApp\Setting
    CopyPath:  HKEY_USERS\<SID>_Classes\Sandbox\DefaultBox\user\current\Software\MyApp\Setting
    ↓ 重定向调用
NtSetValueKey(CopyPath, "value")
    ↓ 写入沙箱注册表
成功写入，真实注册表未修改
```

## 总结

Sandboxie 通过**内核驱动拦截 + 用户态 Hook** 的双层架构，实现了对 Windows 应用程序的完全透明隔离。其核心技术包括：

1. **系统调用拦截**：在内核层拦截所有系统调用
2. **DLL 注入**：在进程早期注入 Hook DLL
3. **路径重定向**：Copy-on-Write 文件系统虚拟化
4. **注册表虚拟化**：独立的注册表命名空间
5. **进程隔离**：完整的进程和 IPC 隔离

这种设计使 Sandboxie 成为 Windows 平台上最成熟、最强大的沙箱解决方案之一，广泛应用于安全测试、恶意软件分析、隐私保护等领域。
