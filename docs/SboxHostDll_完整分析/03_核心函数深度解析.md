## DllMain 函数

### 函数原型

```cpp
BOOL APIENTRY DllMain(
    HMODULE hModule,
    DWORD ul_reason_for_call,
    LPVOID lpReserved
)
```

### 完整源码带注释

```cpp
BOOL APIENTRY DllMain(HMODULE hModule, DWORD ul_reason_for_call, LPVOID lpReserved)
{
    BOOL bRet = TRUE;  // 默认返回成功

    switch (ul_reason_for_call)
    {
    case DLL_PROCESS_ATTACH:  // 进程加载DLL时
        {
            // 声明路径缓冲区（261个宽字符）
            WCHAR wszDLLPath[MAX_PATH + 1];
            
            // 获取当前进程的可执行文件路径
            // GetModuleHandle(NULL) 返回当前进程的.exe句柄
            if (GetModuleFileName(GetModuleHandle(NULL), wszDLLPath, MAX_PATH))
            {
                // 检查路径中是否包含 "OfficeClickToRun.exe"
                if (wcsstr(wszDLLPath, L"OfficeClickToRun.exe"))
                {
                    // 目标进程：创建全局互斥体标识DLL已加载
                    g_hInjectedGlobalNameObj = CreateMutex(
                        NULL,                      // 默认安全属性
                        FALSE,                     // 不初始拥有
                        SBOX_HOST_DLL_LOADED      // 全局名称
                    );
                    bRet = TRUE;  // 允许加载
                }
                else
                {
                    // 非目标进程：拒绝加载
                    bRet = FALSE;
                }
            }
        }
        break;

    case DLL_THREAD_ATTACH:
        // 新线程创建时（当前未处理）
        break;
        
    case DLL_THREAD_DETACH:
        // 线程退出时（当前未处理）
        break;

    case DLL_PROCESS_DETACH:  // 进程卸载DLL时
        // 清理资源：关闭互斥体句柄
        if (g_hInjectedGlobalNameObj)
        {
            CloseHandle(g_hInjectedGlobalNameObj);
        }
        break;
    }
    
    return bRet;  // 返回TRUE允许加载，FALSE拒绝加载
}
```

### 执行流程图

```
DllMain 被调用
    ↓
检查 ul_reason_for_call
    ↓
[DLL_PROCESS_ATTACH]
    ↓
声明 wszDLLPath[261]
    ↓
GetModuleHandle(NULL) → 获取进程.exe句柄
    ↓
GetModuleFileName() → 获取完整路径
    ↓
成功？
    ├─ 否 → 返回 TRUE（默认值）
    ↓
    是
    ↓
wcsstr(路径, "OfficeClickToRun.exe")
    ↓
找到？
    ├─ 否 → bRet = FALSE → 返回 FALSE（拒绝加载）
    ↓
    是
    ↓
CreateMutex("Global\\SboxHostDllLoaded")
    ↓
g_hInjectedGlobalNameObj = 句柄
    ↓
bRet = TRUE
    ↓
返回 TRUE（允许加载）
```

### 关键技术点

#### 1. 进程验证机制

**目的**: 确保DLL只在目标进程中加载

**实现**:
```cpp
// 获取当前进程路径
WCHAR wszDLLPath[MAX_PATH + 1];
GetModuleFileName(GetModuleHandle(NULL), wszDLLPath, MAX_PATH);

// 示例输出:
// C:\Program Files\Microsoft Office\root\Integration\OfficeClickToRun.exe
```

**检查方法**:
```cpp
if (wcsstr(wszDLLPath, L"OfficeClickToRun.exe"))
```

**优点**:
- 简单直接
- 不区分大小写（wcsstr 默认区分，但路径通常一致）
- 适应不同安装路径

**缺点**:
- 可能误判（路径中包含该字符串的其他程序）
- 不够严格

**改进方案**:
```cpp
// 方案1: 只检查文件名
WCHAR* fileName = wcsrchr(wszDLLPath, L'\\');
if (fileName && _wcsicmp(fileName + 1, L"OfficeClickToRun.exe") == 0) {
    // 精确匹配，不区分大小写
}

// 方案2: 检查数字签名
BOOL IsValidOfficeProcess() {
    // 验证可执行文件的数字签名
    // 确保是微软官方的 Office 程序
}
```

#### 2. 全局标识互斥体

**创建**:
```cpp
g_hInjectedGlobalNameObj = CreateMutex(NULL, FALSE, SBOX_HOST_DLL_LOADED);
```

**参数解析**:
- `NULL`: 使用默认安全描述符
- `FALSE`: 创建时不拥有互斥体
- `SBOX_HOST_DLL_LOADED`: `L"Global\\SboxHostDllLoaded"`

**作用**:
1. 标识DLL已成功加载
2. 可被外部程序检测
3. 调试和监控用途

**检测示例**:
```cpp
// 外部程序检测DLL是否已加载
HANDLE hMutex = OpenMutex(SYNCHRONIZE, FALSE, L"Global\\SboxHostDllLoaded");
if (hMutex) {
    printf("SboxHostDll is loaded\n");
    CloseHandle(hMutex);
} else {
    printf("SboxHostDll is not loaded\n");
}
```

#### 3. 返回值控制加载

```cpp
return FALSE;  // 拒绝加载DLL
```

**效果**:
```cpp
// 在非目标进程中
HMODULE hDll = LoadLibrary(L"SboxHostDll.dll");
if (!hDll) {
    DWORD error = GetLastError();
    // error == ERROR_DLL_INIT_FAILED (1114)
    printf("DLL initialization failed\n");
}
```

## InjectDllMain 函数

### 函数原型

```cpp
extern "C" __declspec(dllexport) void InjectDllMain(
    HINSTANCE hSbieDll,
    ULONG_PTR UnusedParameter
)
```

### 完整实现

```cpp
extern "C" __declspec(dllexport) void InjectDllMain(HINSTANCE hSbieDll, ULONG_PTR UnusedParameter)
{
    InitHook(hSbieDll);
}
```

### 函数属性详解

#### extern "C"

**作用**: 使用C链接规范，防止C++名称修饰

**对比**:
```cpp
// 不使用 extern "C"
void InjectDllMain(HINSTANCE, ULONG_PTR);
// 导出名称: ?InjectDllMain@@YAXPAUHINSTANCE__@@K@Z (C++修饰)

// 使用 extern "C"
extern "C" void InjectDllMain(HINSTANCE, ULONG_PTR);
// 导出名称: InjectDllMain (C风格)
```

**为什么需要**:
- Sandboxie 通过名称查找函数
- C风格名称更简单、稳定
- 跨语言兼容性

#### __declspec(dllexport)

**作用**: 将函数导出到DLL的导出表

**查看导出表**:
```bash
# 使用 dumpbin 工具
dumpbin /EXPORTS SboxHostDll.dll

# 输出示例:
# ordinal hint RVA      name
#       1    0 00001000 InjectDllMain
```

**等价的 .def 文件方式**:
```def
; SboxHostDll.def
LIBRARY SboxHostDll
EXPORTS
    InjectDllMain
```

### 调用时机

```
Sandboxie 注入流程:
1. 目标进程启动 (OfficeClickToRun.exe)
2. SbieDrv.sys 拦截进程创建
3. SbieSvc.exe 接收通知
4. SbieDll.dll 被注入到目标进程
5. SbieDll 读取配置，发现需要注入 SboxHostDll.dll
6. SbieDll 调用 LoadLibrary("SboxHostDll.dll")
7. SboxHostDll::DllMain 执行，验证通过
8. SbieDll 调用 GetProcAddress(hDll, "InjectDllMain")
9. SbieDll 调用 InjectDllMain(hSbieDll, 0) ← 此时
10. InitHook 设置 API Hook
11. 目标进程继续正常执行
```

### 为什么需要单独的初始化函数？

**DllMain 的限制**:
```cpp
// ❌ 在 DllMain 中禁止的操作:
LoadLibrary(...)        // 可能死锁
FreeLibrary(...)        // 可能死锁
CreateThread(...)       // 不安全
CoInitialize(...)       // COM初始化不安全
```

**InjectDllMain 的优势**:
```cpp
// ✅ 在 InjectDllMain 中可以安全地:
LoadLibrary(...)        // 安全
CreateThread(...)       // 安全
复杂的初始化逻辑        // 安全
```

**死锁示例**:
```
线程A (DllMain):
  持有 Loader Lock
  ↓
  调用 LoadLibrary("OtherDll.dll")
  ↓
  等待 Loader Lock (被自己持有)
  ↓
  死锁！
```

## InitHook 函数

### 函数原型

```cpp
BOOLEAN InitHook(HINSTANCE hSbieDll)
```

### 完整实现带注释

```cpp
BOOLEAN InitHook(HINSTANCE hSbieDll)
{
    // 检查条件:
    // 1. hSbieDll 有效
    // 2. 尚未设置 Hook (防止重复)
    if (hSbieDll && !__sys_OpenProcessToken)
    {
        // 获取 Advapi32.dll 模块句柄
        HMODULE module = GetModuleHandle(L"Advapi32.dll");
        
        // 获取 OpenProcessToken 函数地址
        void *OpenProcessToken = (P_OpenProcessToken)GetProcAddress(module, "OpenProcessToken");
        
        // 如果找到函数，设置 Hook
        if (OpenProcessToken)
            SBIEDLL_HOOK(SboxHostDll_, OpenProcessToken);
    }
    
    return TRUE;  // 总是返回成功
}
```

### 执行流程

```
InitHook 被调用
    ↓
检查 hSbieDll != NULL ?
    ├─ 否 → 返回 TRUE (跳过Hook)
    ↓
    是
    ↓
检查 __sys_OpenProcessToken == NULL ?
    ├─ 否 → 返回 TRUE (已经Hook过)
    ↓
    是
    ↓
GetModuleHandle("Advapi32.dll")
    ↓
module = Advapi32.dll 句柄
    ↓
GetProcAddress(module, "OpenProcessToken")
    ↓
OpenProcessToken = 函数地址
    ↓
OpenProcessToken != NULL ?
    ├─ 否 → 返回 TRUE (未找到函数)
    ↓
    是
    ↓
SBIEDLL_HOOK(SboxHostDll_, OpenProcessToken)
    ├─ __sys_OpenProcessToken = OpenProcessToken (保存原始地址)
    └─ OpenProcessToken = SboxHostDll_OpenProcessToken (替换)
    ↓
返回 TRUE
```

### SBIEDLL_HOOK 宏详解

#### 宏定义

```cpp
// 简化版定义 (实际实现更复杂)
#define SBIEDLL_HOOK(prefix, func) \
    __sys_##func = (P_##func)func; \
    func = prefix##func;
```

#### 宏展开示例

```cpp
// 调用:
SBIEDLL_HOOK(SboxHostDll_, OpenProcessToken);

// 展开为:
__sys_OpenProcessToken = (P_OpenProcessToken)OpenProcessToken;
OpenProcessToken = SboxHostDll_OpenProcessToken;
```

#### Hook 前后对比

**Hook 前**:
```
应用程序代码:
    OpenProcessToken(hProcess, TOKEN_QUERY, &hToken);
    ↓
    直接调用 Advapi32.dll 中的 OpenProcessToken
    ↓
    系统处理
```

**Hook 后**:
```
应用程序代码:
    OpenProcessToken(hProcess, TOKEN_QUERY, &hToken);
    ↓
    调用 SboxHostDll_OpenProcessToken (我们的Hook函数)
    ↓
    [自定义处理逻辑]
    ↓
    __sys_OpenProcessToken(...) (调用原始函数)
    ↓
    系统处理
```

### 防重复Hook机制

```cpp
if (hSbieDll && !__sys_OpenProcessToken)
//              ^^^^^^^^^^^^^^^^^^^^^^^
//              检查是否已经Hook过
```

**为什么需要**:
```cpp
// 场景: 配置文件错误，重复注入
[DefaultBox]
InjectDll=SboxHostDll.dll
InjectDll=SboxHostDll.dll  // 重复

// 如果不检查:
第一次 Hook:
    __sys_OpenProcessToken = Advapi32!OpenProcessToken ✅
    OpenProcessToken = SboxHostDll_OpenProcessToken ✅

第二次 Hook (如果不检查):
    __sys_OpenProcessToken = SboxHostDll_OpenProcessToken ❌
    OpenProcessToken = SboxHostDll_OpenProcessToken ❌
    
// 结果: 无限递归，栈溢出！
```

## SboxHostDll_OpenProcessToken 函数

这是整个模块最复杂、最核心的函数，将在下一个文档中详细分析。

### 函数概览

```cpp
BOOL SboxHostDll_OpenProcessToken(
    HANDLE ProcessHandle,
    DWORD DesiredAccess,
    PHANDLE phTokenOut
)
```

**功能**: Hook OpenProcessToken API，为沙箱进程提供有效的访问令牌

**复杂度**: ⭐⭐⭐⭐⭐

**代码行数**: ~130 行

**主要步骤**:
1. 调用原始 API 获取令牌
2. 检查目标进程是否在沙箱中
3. 分析令牌的用户 SID
4. 判断是否需要替换令牌
5. 枚举系统进程查找替代令牌
6. 返回替换后的令牌

详细分析请参见下一章节。
