## 模块定义

### 什么是 SboxHostDll？

**SboxHostDll** (Sandbox Host DLL) 是 Sandboxie 沙箱系统的一个专用兼容性模块，它是一个动态链接库（DLL），通过 DLL 注入技术加载到特定的目标进程中，为沙箱环境中的应用程序提供特殊的兼容性支持。

### 模块属性

| 属性 | 值 |
|------|-----|
| **模块名称** | SboxHostDll.dll |
| **模块类型** | 动态链接库 (DLL) |
| **目标进程** | OfficeClickToRun.exe |
| **主要功能** | API Hook + 令牌替换 |
| **注入方式** | Sandboxie 自动注入 |
| **架构支持** | x86, x64 |
| **开发语言** | C++ |
| **依赖框架** | ATL, Windows API |

### 模块定位

```
Sandboxie 生态系统
├── 核心组件
│   ├── SbieDrv.sys (内核驱动)
│   ├── SbieSvc.exe (服务进程)
│   └── SbieDll.dll (用户态 DLL)
├── 用户界面
│   ├── SandMan.exe (控制面板)
│   └── Start.exe (启动器)
└── 兼容性模块 ⭐
    ├── SboxHostDll.dll (本模块)
    └── 其他兼容性 DLL
```

## 问题背景

### Microsoft Office ClickToRun 技术

#### 什么是 ClickToRun？

ClickToRun 是 Microsoft Office 2013 及更高版本使用的一种应用程序虚拟化和流式传输技术：

- **虚拟化技术**: 使用 App-V (Application Virtualization) 技术
- **流式安装**: 可以在下载完成前开始使用 Office
- **自动更新**: 后台自动更新，无需用户干预
- **独立环境**: 在虚拟环境中运行，与系统隔离

### 沙箱环境中的问题

#### 问题 1: 特殊账户令牌限制

OfficeClickToRun.exe 服务使用特殊的 Windows 账户运行：

**虚拟账户 (Virtual Account)**
- SID 格式: `S-1-5-100-*`
- 特点: 无密码、自动管理、隔离性强
- 用途: 服务账户，提供最小权限

**匿名登录 (ANONYMOUS LOGON)**
- SID: `S-1-5-7`
- 特点: 无身份验证、受限访问
- 用途: 临时访问、最小权限场景

#### 问题 2: 沙箱令牌限制

当 OfficeClickToRun.exe 在 Sandboxie 沙箱中运行时：

```
正常环境:
OfficeClickToRun.exe → 获取虚拟账户令牌 → 访问系统资源 ✅

沙箱环境:
OfficeClickToRun.exe → 获取沙箱化的虚拟账户令牌 → 访问受限 ❌
                       (令牌权限被沙箱进一步限制)
```

**导致的问题**:
- ❌ 无法访问必要的系统资源
- ❌ 无法读取配置文件
- ❌ 无法启动 Office 应用程序
- ❌ 功能异常或崩溃

#### 问题 3: 令牌验证失败

Office 应用程序在启动时会验证 ClickToRun 服务的令牌：

```cpp
// Office 应用程序的伪代码
HANDLE hProcess = OpenProcess(..., ClickToRunServicePID);
HANDLE hToken;
if (OpenProcessToken(hProcess, TOKEN_QUERY, &hToken)) {
    // 验证令牌的有效性
    if (!ValidateServiceToken(hToken)) {
        // 令牌无效，拒绝启动 ❌
        return ERROR_ACCESS_DENIED;
    }
}
```

在沙箱环境中，这个验证可能失败。

### 解决方案需求

为了解决上述问题，需要一个模块能够：

1. ✅ **拦截令牌请求**: Hook `OpenProcessToken` API
2. ✅ **识别特殊账户**: 检测虚拟账户和匿名登录令牌
3. ✅ **查找有效令牌**: 在主机进程中找到有效的替代令牌
4. ✅ **保持会话一致**: 确保登录会话 SID 匹配
5. ✅ **透明替换**: 对应用程序完全透明

### 模块分层

#### 第 1 层: 注入控制层
- **责任**: 由 Sandboxie 核心负责
- **功能**: 检测目标进程、执行 DLL 注入
- **位置**: SbieDll.dll / SbieDrv.sys

#### 第 2 层: 入口验证层
- **责任**: dllmain.cpp
- **功能**: 验证目标进程、初始化资源
- **关键函数**: `DllMain()`, `InjectDllMain()`

#### 第 3 层: Hook 管理层
- **责任**: SboxHostDll.cpp - InitHook()
- **功能**: 设置 API Hook、管理函数指针
- **关键技术**: SBIEDLL_HOOK 宏

#### 第 4 层: 业务逻辑层
- **责任**: SboxHostDll.cpp - SboxHostDll_OpenProcessToken()
- **功能**: 令牌分析、查找、替换
- **关键技术**: ATL 安全类、进程枚举

## 技术选型

### 编程语言: C++

**选择原因**:
- ✅ 系统级编程的标准语言
- ✅ 直接访问 Windows API
- ✅ 高性能、低开销
- ✅ 与 Sandboxie 核心代码一致

### ATL (Active Template Library)

**选择原因**:
- ✅ 提供高级安全对象封装
- ✅ `CAccessToken` 类简化令牌操作
- ✅ `CSid` 类简化 SID 处理
- ✅ 自动资源管理（RAII）

**关键类**:

```cpp
// ATL 安全类的使用
ATL::CAccessToken token;      // 令牌包装类
token.Attach(hToken);          // 附加令牌句柄
token.GetUser(&userSid);       // 获取用户 SID
token.GetLogonSid(&logonSid);  // 获取登录会话 SID
token.Detach();                // 分离句柄（不关闭）
// token 析构时自动关闭句柄（如果未 Detach）
```

### Windows API

**核心 API**:

| API | 用途 | 所在 DLL |
|-----|------|----------|
| `OpenProcessToken` | 获取进程访问令牌 | Advapi32.dll |
| `EnumProcesses` | 枚举系统进程 | Psapi.dll |
| `OpenProcess` | 打开进程句柄 | Kernel32.dll |
| `GetModuleFileName` | 获取进程路径 | Kernel32.dll |
| `CreateMutex` | 创建互斥体 | Kernel32.dll |

### Sandboxie API

**核心 API**:

```cpp
// 查询进程信息
ULONG SbieApi_QueryProcessInfo(
    HANDLE ProcessId,
    ULONG InfoClass
);

// 返回值包含标志位
#define SBIE_FLAG_VALID_PROCESS  0x00000001  // 进程在沙箱中
```

### Hook 技术: SBIEDLL_HOOK 宏

**定义位置**: `core/dll/sbiedll.h`

**使用方式**:
```cpp
// 宏定义（简化）
#define SBIEDLL_HOOK(prefix, func) \
    __sys_##func = (P_##func)func; \
    func = prefix##func;

// 使用示例
SBIEDLL_HOOK(SboxHostDll_, OpenProcessToken);

// 展开后等价于:
__sys_OpenProcessToken = (P_OpenProcessToken)OpenProcessToken;
OpenProcessToken = SboxHostDll_OpenProcessToken;
```

## 设计原则

### 1. 单一职责原则 (SRP)

每个模块只负责一个特定功能：

- **dllmain.cpp**: 只负责 DLL 生命周期管理
- **SboxHostDll.cpp**: 只负责 Hook 和令牌处理
- **头文件**: 只负责声明和定义

### 2. 最小权限原则

- 只在必要时替换令牌
- 只针对特定的 SID 类型
- 保持原有的访问权限级别

### 3. 防御性编程

```cpp
// 检查指针有效性
if (phTokenOut) {
    *phTokenOut = hToken;
}

// 检查函数指针
if (__sys_OpenProcessToken) {
    bRet = __sys_OpenProcessToken(...);
}

// 验证目标进程
if (wcsstr(wszDLLPath, L"OfficeClickToRun.exe")) {
    // 只在目标进程中激活
}
```

### 4. 资源管理 (RAII)

```cpp
// 使用 ATL 类自动管理资源
{
    ATL::CAccessToken token;
    token.Attach(hToken);
    // ... 使用 token
    token.Detach();  // 手动分离，不自动关闭
}  // 如果未 Detach，析构时自动关闭

// 手动管理句柄
HANDLE hProc = OpenProcess(...);
if (hProc) {
    // ... 使用句柄
    CloseHandle(hProc);  // 确保关闭
}
```

### 5. 透明性原则

- Hook 函数对应用程序完全透明
- 保持原始 API 的行为和错误码
- 只在必要时修改返回值

### 注入时机

```
进程启动流程:
1. 用户启动 OfficeClickToRun.exe
         ↓
2. SbieDrv.sys 拦截进程创建
         ↓
3. SbieSvc.exe 接收通知
         ↓
4. 检查配置文件，确定需要注入的 DLL
         ↓
5. SbieDll.dll 被注入到目标进程
         ↓
6. SbieDll.dll 初始化，读取配置
         ↓
7. SboxHostDll.dll 被注入 ⭐
         ↓
8. SboxHostDll::DllMain 执行
         ↓
9. SboxHostDll::InjectDllMain 被调用
         ↓
10. Hook 设置完成
         ↓
11. 进程继续正常执行
```
