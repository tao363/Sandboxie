# Sandboxie-Plus — 核心信念

这些信念指导 AI agent 在本项目中的所有决策。当遇到模糊情况时，回到这些信念来做判断。

---

## 工程原则

### 1. 安全优先

**沙箱的本质是安全隔离。** 任何修改都必须考虑对隔离安全性的影响。

- 内核驱动代码必须经过安全专家审查
- 所有来自沙箱进程的数据都不可信
- 权限检查不能被绕过

### 2. 最小权限原则

**沙箱进程应该只有完成其功能所需的最小权限。**

- 默认拒绝，显式允许
- 受限 Token 创建后不应提升权限
- 敏感操作需要用户确认

### 3. 透明隔离

**用户不应感知到沙箱的存在，除非发生安全事件。**

- 文件操作透明重定向
- 注册表操作透明重定向
- 错误信息清晰易懂

### 4. 向后兼容

**新版本不应破坏现有用户的配置和使用习惯。**

- 配置文件格式保持兼容
- API 接口保持稳定
- 弃用功能需要过渡期

### 5. 性能敏感

**沙箱不应该显著降低系统性能。**

- Hook 开销最小化
- 避免不必要的内存分配
- 路径缓存优化

## 黄金规则

### 代码层面

1. **偏好共享工具函数，而非手写辅助函数**  
   集中管理不变量，避免重复代码

2. **在边界处校验数据，而非在内部推测数据形状**  
   驱动和服务必须验证所有来自沙箱进程的数据

3. **偏好可组合的小函数，而非包含复杂逻辑的大函数**  
   便于测试、审查和复用

4. **使用项目内存池，而非直接调用系统分配器**  
   便于内存追踪和调试

5. **使用安全字符串函数，而非不安全的版本**  
   `Sbie_snwprintf` 而非 `swprintf`

### 架构层面

1. **分层架构不可违反**  
   高层可以依赖低层，低层不能依赖高层

2. **内核代码保持精简**  
   复杂逻辑放到用户态服务中

3. **GUI 通过 API 层访问核心功能**  
   禁止 GUI 直接调用驱动

4. **配置修改通过服务代理**  
   确保配置一致性

## 禁止事项

以下行为是 **绝对禁止** 的：

### 内核驱动

- ❌ 使用标准 C 运行时函数
- ❌ 使用浮点运算
- ❌ 直接信任用户态指针
- ❌ 在中断上下文中进行阻塞操作
- ❌ 绕过权限检查

### 用户态代码

- ❌ 在日志中输出敏感数据（密码、密钥）
- ❌ 绕过 API 层直接调用驱动
- ❌ 修改共享头文件而不更新所有依赖模块
- ❌ 使用不安全的字符串函数

### 安全相关

- ❌ 存储明文密码
- ❌ 绕过沙箱隔离
- ❌ 在沙箱进程中执行高权限操作
- ❌ 忽略来自沙箱进程的数据验证

## 决策框架

当面临设计决策时，按以下顺序考虑：

1. **安全性** — 这个决策会影响隔离安全性吗？
2. **兼容性** — 这个决策会破坏现有功能吗？
3. **性能** — 这个决策会显著影响性能吗？
4. **可维护性** — 这个决策会增加维护负担吗？
5. **用户体验** — 这个决策会改善用户体验吗？
